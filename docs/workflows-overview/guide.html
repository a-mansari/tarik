Tarik repository guide

For a developer joining the project: what Tarik is, every file and folder of the repository and what it is for, and the day-to-day loop. The README is the reference; this is the tour.

What Tarik is

Tarik is an accounting assistant for Moroccan cabinets (accounting firms) using Experio, an Odoo 15 app. A clerk writes to Tarik by chat or email, attaches invoices, bank statements or a FEC, and Tarik puts them into Experio through Experio's own screens and wizards. Nothing is invented: a model (MiniMax-M3) only reads scans and the client's words; every write is a fixed Python step.

The pieces, each a Docker service in docker-compose.yml:

  • n8n (patched, n8n/): hosts one native agent per cabinet ("Tarik - GECAFISC" and 7 more) and three workflows. The agent finds the dossier and hands the work to a workflow; the workflow calls the Python tools step by step.
  • tarik-mcp (mcp/): the Python tools, served over MCP at http://tarik-mcp:8000/c/<cabinet>/mcp. One address per cabinet, so a call can only ever work in the cabinet it named.
  • tarik-mail-watch (mcp/watcher.py, same image): watches each cabinet's mailbox over IMAP IDLE and wakes the email workflow.
  • postgres: Tarik's own data (one schema per cabinet, from mcp/tarik/core/cabinet.sql) and n8n's data.
  • vault: every secret and per-cabinet setting (secret/tarik/shared, secret/tarik/cabinets/<cabinet>). The cabinets are those Vault paths.

A cabinet is named by its exact Experio database (experio_cabinet_8). That name is its MCP address, its Vault path and its Postgres schema. The agent never sees Odoo, a URL or a setting: it is "Experio" everywhere.

A request flows like this: an email arrives, the watcher stores it and wakes "Tarik - Emails"; that workflow asks the cabinet's agent; the agent calls "Tarik - Traitement" (invoices and statements) or "Tarik - Dossier" (a new dossier, a FEC, or a change to a dossier); each node of those workflows is one MCP tool in mcp/tarik/; the run's summary comes back to the agent, then to the client. Chat follows the same path without the watcher and the email workflow.

The agent only chooses which workflow to call and fills a few fields; each workflow node is one Python tool, and only those tools write to Experio. Postgres also holds n8n's own data.

mcp/: the Python tools

Every tool is a Python function decorated with @server.tool() (or @step_tool, which also copies the invoice, file and dossier ids into the result so n8n can route on them). Importing a module registers its tools. A tool returns a dict with status (ok, wait, question, stop) and a French message the client reads; a ToolError is the only text that reaches the agent on failure.

mcp/tests/: the tests

Tests run in a throwaway tarik-mcp container on your working copy, against the test database tarik_test (never the cabinets' own) with settings from the environment instead of Vault. Each test has one category marker: security, functionality, communication, technical, style, plus live (the real n8n) and llm (the real model, slow, billed), which only run when asked.

emails/Threads, inbox reading, sending and whitelist, the agent call, the watcher.

Day to day

Rules the code keeps, and tests enforce

  • Every dossier tool needs a real dossier id from find_dossier; every invoice tool a real draft of one of the cabinet's dossiers.
  • The model never decides a value: an ICE, an amount, a name is taken only when the client wrote it; a choice only among what the question proposed.
  • DRY_RUN=1 per cabinet (the default): drafts and statements are created, nothing else is written; replies start with MODE TEST.
  • A setting is either the cabinet's own or shared, never both, and never shown to the agent.
  • One module per invoice step; a step tells the client what it did in one French sentence; routine outcomes are left out of the summary.

Changing Python

  1. Edit a module under mcp/tarik/.
  2. python3 mcp/tests/run.py runs the tests that cover your change; --all for everything. Ruff lint and format are part of the style tests.
  3. docker compose up -d --build --force-recreate tarik-mcp tarik-mail-watch.

Changing a workflow or the agents

  1. Edit workflows/build_tarik_*.py or workflows/steps.py, run the builder.
  2. docker compose cp the JSON into n8n, n8n import:workflow, n8n publish:workflow --id=..., docker compose restart n8n (README has the exact commands).
  3. A change to tarik-agent.json or a skill: python3 workflows/build_tarik_agents.py. It updates all cabinets and republishes the agents that were published.
  4. python3 docs/workflows-overview/build.py to regenerate the team overview.

Changing a prompt: edit instructions/tools/*.md, restart tarik-mcp.

Adding a cabinet: give Tarik a user in that cabinet's Experio, add its database name to CABINETS in build_tarik_agents.py, run it, put the agent id and the cabinet's settings in Vault under secret/tarik/cabinets/<cabinet>, restart tarik-mcp (its schema is made at start).

Where to look when something goes wrong: docker compose logs tarik-mcp (every Experio refusal is logged with the tool and the invoice), the run's rows in tarik_results, the thread's state in tarik_mail_threads, and n8n's execution of the workflow.
